# Evidence-led artifact investigation

For a requested binary or application investigation, adopt REA's target-first workflow. Identify the supplied artifact and the exact feature to explain, inspect available analysis capabilities, then select the appropriate native, managed, JavaScript, Electron, firmware, or browser evidence path. Use provider discovery only when it resolves a real requirement. Separate static observations, runtime observations, inference, and unresolved questions in the reply.

Trace a feature to concrete modules, symbols, resources, call relationships, or observed behavior before proposing a reconstruction. Preserve artifact identities and evidence references so a later reader can assess the conclusion. Report missing providers or unsupported targets directly. Registering these instructions does not install a decompiler, attach a debugger, launch an application, or grant access to a target. Do not run code extracted from an artifact. Every analysis process or runtime interaction must use an available registered tool and the kernel's authorization boundary.

Some of this is now internal rather than delegated. Artifact identification and structural layout, a typed WASM import/export interface and its comparison, and a static read of EVM bytecode are native tools here: they read bytes, they are deterministic, and they are replayable. Prefer them over describing an external capability, and state their declared limitations rather than implying completeness. A WASM or EVM reading that reports a partial state has not failed; an absence inside a partial result is not evidence that something is missing from the artifact, and a selector candidate recovered by scanning constants is not a confirmed interface.

The rest of the surface stays external, and not because it is unbuilt. A device, a debugger, a decompiler, a packer or a live browser cannot be read as a pure function of a declared input, so it cannot be replayed, and the catalog records that reason per tool. When a request needs one, say that it requires separately provisioned tooling and explicit authorization instead of proposing it as available. Catalogued REA tool names are indexed data describing another program; naming one grants nothing.

## Proven by training

Each line below came from a plan that ran through this kernel, behaved exactly as predicted,
and replayed. These are observations about behaviour, not permissions: nothing here grants
anything, and an unreviewed source stays unreviewed.

- `artifact.analysisView` — artifact.analysisView checks a record set against itself and names each problem separately: one id reused for two different digests, a record carrying no digest, and a reference to something the view never contained. It says outright that a pure tool reaches nothing, so it can prove internal consistency and never authenticity.
- `artifact.androidManifest`, and 20 other tools alike — artifact.androidManifest answers a file that is not its format with supported:false and a stated reason, never by throwing, and the SHA-256 it reports is the digest of exactly the bytes the fixture wrote — compared against a value computed independently, so it cannot be the hash of a different or partial read. It returns every key it declares even when it could parse nothing, so a caller never branches on whether a key is present, and it marks the result untrusted because bytes from a file are evidence about that file and nothing more.
- `artifact.appleGraph` — artifact.appleGraph refuses a file that declares no plist element with supported:false and a reason, and returns a null bundle with an empty edge list rather than a half-built graph. A partial graph that looked real would be worse than no graph.
- `artifact.compareApplicationVersions` — artifact.compareApplicationVersions keys entries by kind and name and, with a digest on both sides, separates added, removed, changed and unchanged. An entry with no declared kind is keyed as unspecified rather than silently matched against a differently-kinded one.
- `artifact.compareApplicationVersions` — artifact.compareApplicationVersions reports present-both, not unchanged, when only one side carries a digest: both versions declare the entry but a change cannot be decided. Calling that unchanged would turn a missing digest into a false claim of equality.
- `artifact.compareHar` — artifact.compareHar consumes the flat entries artifact.harCapture emits and keys a request by method, origin and path only. Query strings, timing and bodies are deliberately outside the key, so two calls differing only in a query parameter compare as the same request.
- `artifact.compareJsExports` — artifact.compareJsExports keys an export by name and kind together, so the same name re-exported as a different kind reads as one removal plus one addition rather than a change. It states that a different value or signature behind an unchanged name is invisible to it.
- `artifact.compareManagedMembers` — artifact.compareManagedMembers keys a member by declaring type, name and kind, and reports an attribute change as changed while showing both attribute lists. Signatures are not part of the key, so an overload set collapses to one member.
- `artifact.compareSourceToBundle` — artifact.compareSourceToBundle separates present, absent and bundle-only, and attaches to every absence the reason that a minifier renaming the export would look identical. Absence of an export from a bundle is therefore never reported as evidence that it was removed.
- `artifact.compareWasmInterfaces` — artifact.compareWasmInterfaces reports unknown rather than unchanged when a signature on either side was never decoded, and when one interface is partial it says plainly that an absence there is not evidence of removal. Equality is only ever concluded from two complete readings.
- `artifact.dexClass`, and 4 other tools alike — artifact.dexClass takes an argument beyond the path, and still refuses a file that is not its format with supported:false, a reason, and the digest of exactly the bytes it read. Where findings would go it returns an empty list or an explicit null rather than omitting the key or guessing — so a caller reading the result cannot tell a parse that found nothing from a parse that failed, except by the field that says which. The extra argument narrows what is being asked; it never loosens what is accepted.
- `artifact.evmInterface` — artifact.evmInterface digests the carrier file and the decoded bytecode separately, and the two genuinely differ for hex input: the same contract delivered as hex text and as raw bytes is one bytecode in two different files, and only the bytecode digest identifies the contract. The opcode tally is a scan rather than a disassembly — five bytes decode to three instructions of which two are pushes — and its `undefined` and `undefinedCount` fields are named for undefined EVM opcodes, not for a missing value. Absent trailing metadata is null rather than an empty object, so "there was none" and "there was some and it was empty" stay distinguishable.
- `artifact.firmware` — artifact.firmware scans for known magics and reports exactly what it found and where: one region for one UBI signature, a tally beside it, the byte length it examined, and the digest of those same bytes. Some signatures are only meaningful at a fixed offset, so an anchored magic appearing elsewhere is deliberately not treated as a hit — which is why the region count is worth asserting rather than just the presence of a list.
- `artifact.firmwareRegion` — artifact.firmwareRegion reads a declared window of a file rather than the whole of it, and echoes back the offset and length it actually read, so an unknown blob can be examined in bounded pieces without ever loading it entirely.
- `artifact.harCapture` — artifact.harCapture reports a capture structurally and copies no headers, cookies or bodies out of it: a HAR is full of credentials, so the reader withholds them by construction rather than by redaction.
- `artifact.htmlScripts`, and 2 other tools alike — artifact.htmlScripts is a lexical scan, so supported:true means only that the text could be scanned and never that the file is what you hoped. It blanks comments, strings, template literals and regular expressions first while preserving every byte offset, so a match cannot fire on a keyword inside a comment and a reported position still refers to the real file.
- `artifact.importManagedReconstruction` — artifact.importManagedReconstruction accepts a reconstructed member only where the observed artifact declares one with the same name and kind, so a member nobody observed is rejected and a member reconstructed under the wrong kind is rejected too. Coverage counts names, and the tool says outright that it is no statement about behavioural correctness.
- `artifact.inspect` — A file named .png whose bytes are a zip is reported as a zip: artifact.inspect reads content, so a wrong extension cannot mislead anything downstream of it.
- `artifact.inspect` — artifact.inspect binds every claim to a digest of the bytes it read, so a later statement about a file can be checked against the exact content that produced it.
- `artifact.inspect` — artifact.inspect identifies png from magic bytes alone, never from the file extension, and reports the SHA-256 of exactly the bytes it read.
- `artifact.inspect` — artifact.inspect identifies wasm from magic bytes alone, never from the file extension, and reports the SHA-256 of exactly the bytes it read.
- `artifact.inspect` — artifact.inspect identifies zip from magic bytes alone, never from the file extension, and reports the SHA-256 of exactly the bytes it read.
- `artifact.inspect` — artifact.inspect reports a PE entry point three ways because they are three different numbers, and confusing them is the most direct route to confidently wrong disassembly. AddressOfEntryPoint is a relative virtual address; the bytes live at a file offset that differs by the gap between a section virtual address and its PointerToRawData; and the address the code believes it runs at is the image base plus the RVA. On a real Windows binary that gap is 0xC00, so handing the RVA to a disassembler as an offset decodes bytes three kilobytes away and reports success on every one of them, because a stream of x86 bytes is almost always decodable as something. The conversion needs the section table, so the section table is reported too, and when no section covers the RVA the offset key is absent rather than null or zero: canonical refuses undefined, and a guessed offset is worse than a stated gap. The same distinction applies to ELF, where the mapping comes from the PT_LOAD segments instead.
- `artifact.jsApplication` — artifact.jsApplication walks a module graph from a single entry and resolves the files it reaches, reporting resolved modules, external packages and unresolved specifiers as separate lists, so a dependency it could not find is never quietly counted as one that was not there.
- `artifact.jsSemantics` — artifact.jsSemantics reports constructs it recognised by scanning and says plainly that it is a scan rather than a parse: it describes what the text contains, not what the program does when it runs.
- `artifact.obligationLedger` — artifact.obligationLedger closes an obligation only for a passing verifier with replay authority that cited evidence. A passing verifier whose authority is merely inferred leaves it open, a failing verifier leaves it open, and a static fact with nothing to verify it raises a candidate rather than a conclusion.
- `artifact.packetFields` — artifact.packetFields decodes a frame as a stack of layers rather than a flat record, so an Ethernet frame carrying IPv4 carrying TCP is three layers and not one dictionary with the names run together. decoded counts the frames it got all the way through, which is deliberately not the same as the number of frames: a capture whose link type this reader cannot name still lists its frames and decodes none of them, and a caller that read only the frame count would not be able to tell those apart.
- `artifact.pcap` — Given a real capture, artifact.pcap reports each record by where it sits rather than only how long it is: the offset of the record and the offset of its payload are separate facts, and both are needed to quote a packet from the file by digest. sliced:false says the whole frame was captured, which is the difference between a packet and a prefix of one - a snapshot length shorter than the frame is the normal way a capture lies by omission, and the reader names it per packet instead of per file.
- `artifact.peResources` — Given a real PE, artifact.peResources walks the resource directory as the tree it is - type, then name or id, then language - rather than flattening it. Ghidra’s own pdb.exe carries exactly one resource type, id 24, which is the application manifest, and reporting both the numeric id and the name it maps to matters because the id is what is in the file and the name is this reader’s interpretation of it. named:false says this level is addressed by number, which is the usual case and the one a reader that only reported names would silently misrepresent.
- `artifact.reconstructionCoverage` — artifact.reconstructionCoverage answers unknown, never covered, for an obligation closed on an inferred observation, and names the probe that would settle it: replace the inference with a replay observation. An inferred observation can never promote coverage, which is what keeps a chain of plausible reasoning from being mistaken for evidence.
- `artifact.reconstructionCoverage` — artifact.reconstructionCoverage distinguishes an obligation closed on weak evidence from one closed on evidence nobody supplied: both are unknown rather than covered, but each names its own probe, so the reason coverage failed is never guesswork.
- `artifact.reconstructionCoverage` — artifact.reconstructionCoverage reports covered only when every obligation scoped to the named boundary is closed and backed by a replay observation, and it scopes strictly: an obligation belonging to another boundary is not counted either for or against this one.
- `artifact.recoverSources` — artifact.recoverSources lists what a map can give back and digests each one without returning any of it: content is null until a caller names a single source, which keeps a listing of a large bundle from being a copy of it. Each entry carries hasContent, because a map that lists a source and omits its text can name a file it cannot recover - and the digest is computed over the recovered text, so the bytes a plan later quotes are the bytes that were measured here.
- `artifact.sourceMap` — A version 3 source map is read for the two things that can be checked against the bundle: which sources it claims and how many mappings it carries. The count is of decoded segments rather than of lines, because a map with many lines and few segments describes almost nothing - and the digest is of the map file itself, so a recovered source can be traced to the exact map that produced it rather than to a map with the same name.
- `artifact.sourceMap` — artifact.sourceMap decodes VLQ mappings field by field rather than trusting a library: only generatedColumn resets per line, so a decoder resetting the others would report plausible wrong origins.
- `artifact.sqlite` — Given a database written by SQLite itself, artifact.sqlite reads the header fields that decide how every other byte is interpreted - page size, page count, text encoding, schema format - and then the schema objects with the SQL that defined them. An index and a view are listed beside the table they belong to, each with the root page it lives on, so a claim about a database can name where in the file it came from. The reader is a reader: it never opens the database, which is why a file whose header says 4096 and whose pages are something else is reported as it is rather than refused by an engine.
- `artifact.traceFeature` — artifact.traceFeature matches a feature term against names and source paths in a supplied inventory, case-insensitively, and reports each match as a candidate to look at. It states that it is not a dataflow or call trace: a match never establishes that an entry implements the feature, and an absence means only that the inventory does not mention the term.
- `artifact.verifyManagedNativeBoundaries` — artifact.verifyManagedNativeBoundaries checks each boundary against a list of available module names, so satisfied means the module was present and explicitly not that the named export exists inside it. A boundary naming no module at all is unknown rather than missing, because there was nothing to check it against.
- `artifact.wasmInterface` — artifact.wasmInterface reads a module header and its section table directly rather than instantiating anything, so a module is described without ever being run. It reports its own state, because a module it could only partly decode must not read as one it decoded fully.
- `artifact.webBundle` — artifact.webBundle looks for bundler markers in text and reports which it saw. A marker is evidence that a bundler touched the file, not proof of which one or of what it did.
